# 债基再平衡助手 v2

一个轻量、静态、本地计算的人民币债券基金再平衡工具。输入当前持仓与资金变动后，生成金额守恒、可解释、容易执行的调整方案。

👉 [在线使用](https://zzpice.github.io/rmb-bond-rebalancer/)

## 组合

| 基金 | 代码 | 目标比例 |
| --- | --- | ---: |
| 景顺长城景盛双息 A | 002065 | 50.00% |
| 易方达增强回报 A | 110017 | 33.33% |
| 广发纯债 A | 270048 | 12.50% |
| 长城短债 A | 007194 | 4.17% |

目标比例使用整数基点表示，合计严格为 100.00%。目标比例是唯一战略锚点，再平衡规则只决定何时交易以及触发后需要退回多深。

## v2 决策规则

每次计算只使用当前持仓与本次资金变动，不记录或推断历史原因。

- **5 / 25 外层触发**：单项容差取 5 个百分点与目标权重的 25% 中较小者。边界属于安全区间，只有严格越过外层才触发内部再平衡。
- **80% 回调区间**：触发后，各基金需要进入“目标 ± 80% × 外层容差”的统一回调区间。它不是新的目标配置，只用于提供滞回缓冲，避免刚调整完又再次触发。
- **最小必要交易**：在全部基金进入 80% 回调区间且金额守恒的约束下，选择内部换手最小的可行结果；不要求回到目标，也不要求机械落在某一条边界线上。
- **新增资金**：优先按目标缺口补低配；只有资金流后仍严格越过 5 / 25 外层时，才进入同一 80% 回调区间做最小内部转换。
- **取出资金**：继续使用 v2.0.1 规则。先利用本次提款纠正提款前已经存在的高配越界；剩余提款依次从长城短债、广发纯债、两只固收增强中取出。两只固收增强最终需要承担提款时，按当时剩余持仓比例分摊。
- **取现不追加内部转换**：本次提款造成的新高配或低配均作为本次提款结果保留，不在同一方案里反向买卖恢复区间。

所有金额以整数 CNY 计算并使用最大余数法处理比例分配尾差，因此始终满足：

- 最终持仓合计 = 当前持仓合计 + 资金变动
- 各基金最终持仓 = 当前持仓 + 对应操作
- 所有操作净额 = 资金变动
- 最终持仓不为负数
- 取出资金时基金间转换 = 0
- 非取现路径未触发外层时不做内部转换
- 非取现路径一旦触发，最终全部进入 80% 回调区间，且内部换手达到该约束下的最小值

## 界面

应用只保留三个独立视图：

- **工作台**：当前持仓、资金变动、组合概览与生成方案。
- **方案**：本次执行清单、调整前后与计算说明；生成成功后自动进入。
- **规则**：5 / 25 外层触发、80% 回调区间和各资金变动场景的固定决策规则。

三个视图共用同一静态应用状态，不使用路由框架，也不通过 URL、浏览器存储或多份 HTML 传递持仓。生产界面不提供“载入示例”入口。

## 架构

项目不使用前端框架或构建步骤，可直接部署到 GitHub Pages。

| 文件 | 职责 |
| --- | --- |
| src/portfolio.js | 基金数据、输入精度、目标金额、5 / 25 外层与 80% 回调区间 |
| src/rebalance.js | 资金流分配、取现顺序、回调区间最小换手、必要配平与不变量校验 |
| src/format.js | 金额与比例显示 |
| src/app.js | 三视图状态、渲染、交互和 PWA 更新 |
| styles/app.css | Dashboard 视觉与响应式布局 |
| service-worker.js | 离线缓存与版本更新 |

持仓不会上传、写入数据库或保存在浏览器中；只有外观偏好会保存在本机。

## 开发与测试

安装依赖后运行 npm test。

- Node 单元测试验证 5 / 25 外层、80% 回调、最小换手、取现顺序和随机场景不变量。
- Playwright 只验证关键用户流程、三视图导航、输入错误、响应式布局和 PWA 外壳。
- GitHub Actions 在 main、功能分支和 Pull Request 上运行完整测试。
